# حسابات الفروع — نسخة سطح المكتب (Electron)

## البناء السريع على Windows
انقر مرتين على الملف **`build_desktop.bat`** (يطلب صلاحية المسؤول، ثم يثبّت ويبني تلقائيًا) وسيظهر المثبّت داخل مجلد `dist`.

## التشغيل والبناء على Windows (يدويًا)
1. ثبّت **Node.js** (النسخة LTS) من nodejs.org.
2. افتح PowerShell داخل هذا المجلد ونفّذ:
   - `npm install`  (مرة واحدة، يحتاج إنترنت)
   - `npm start`    (لتجربة البرنامج)
   - `npm run dist` (لبناء ملف التثبيت `.exe`، وسيظهر داخل مجلد `dist`)
3. ثبّت البرنامج من الملف الناتج. سيُظهر Windows تحذير SmartScreen لأن الملف غير موقّع برقمية رسمية؛ اختر "مزيد من المعلومات ← تشغيل على أي حال".
4. لتغيير الأيقونة: ضع ملف `icon.ico` (256×256) داخل مجلد `build` قبل البناء.

## أين تُحفظ البيانات؟
في `C:\Users\<الاسم>\AppData\Roaming\ShopAccounts\data.json` على هذا الجهاز فقط.

## النسخ الاحتياطي
- تلقائي: عند فتح البرنامج وإغلاقه وكل ساعة إن تغيّرت البيانات، داخل مجلد `backups` بجوار البيانات.
- يُحتفظ بكل نسخ آخر يومين، ثم بنسخة لكل يوم حتى 60 يومًا.
- من **الإعدادات ← النسخ الاحتياطي**:
  - «مجلد نسخ إضافي»: حدّد فلاشة أو مجلد OneDrive/Google Drive لتُنسخ إليه كل نسخة تلقائيًا (موصى به جدًا).
  - «نسخة الآن إلى مجلد»: نسخة يدوية في المكان الذي تختاره.
  - «استرجاع من ملف»: يستبدل البيانات بمحتوى النسخة بعد أن يحفظ نسخة أمان من بياناتك الحالية.

## نقل بيانات النسخة السحابية
من نسخة Claude: **الإعدادات ← تصدير JSON**، ثم في البرنامج المكتبي: **استرجاع من ملف** واختر الملف.

## ملاحظات
- البيانات على جهاز واحد: مناسبة لشخص واحد يدوّن الحسابات. لا تُشغّل البرنامج على جهازين وتتوقع تزامنًا بينهما.
- التقارير والسندات تُحفظ كملف PDF وتُفتح تلقائيًا للطباعة، والجداول بصيغة CSV تُفتح في Excel.

## التحديث من GitHub
البرنامج يفحص GitHub Releases بعد فتحه بثوانٍ، وتجد في **الإعدادات ← التحديثات** زر الفحص والتنزيل والتثبيت. قبل التثبيت تُحفظ نسخة احتياطية تلقائيًا.

### إعداد مرة واحدة
1. أنشئ حسابًا في github.com ومستودعًا **عامًا (Public)** باسم `shop-accounts`.
2. في `package.json` غيّر `YOUR_GITHUB_USERNAME` إلى اسم حسابك (قسم `build.publish`).
3. ارفع المشروع للمستودع (الملف `.gitignore` يستثني `node_modules` و`dist`). **لا ترفع ملفات بياناتك**؛ فهي أصلًا خارج المشروع.
4. من GitHub: Settings ← Developer settings ← Personal access tokens ← **Tokens (classic)** ← أنشئ توكنًا بصلاحية `repo`.
5. في PowerShell: `$env:GH_TOKEN="التوكن"` (لا تضعه داخل أي ملف ولا تشاركه).

### إصدار تحديث جديد
1. غيّر `"version"` في `package.json` إلى رقم أكبر (مثل `1.0.1`).
2. نفّذ `npm run release`؛ يبني المثبّت ويرفعه مع ملف `latest.yml` إلى Release بحالة مسودة.
3. افتح المستودع ← Releases ← افتح المسودة واضغط **Publish release**.
4. تظهر الأجهزة المثبّتة الإصدار الجديد في الإعدادات ← التحديثات.

### ملاحظات
- التثبيت الأول يتم يدويًا من ملف `.exe`؛ ويعمل التحديث فقط على النسخة المثبّتة وليس على `npm start`.
- المستودع العام يعني أن الكود ظاهر للجميع، لكن بياناتك التجارية تبقى على جهازك.
- المستودع الخاص يحتاج توكنًا داخل التطبيق، ولا أنصح به.
- يجب أن يكون رقم الإصدار الجديد أكبر من المثبّت، وإلا لن يُعرض التحديث.

## الخط العصري (Tajawal)
1. من fonts.google.com ابحث عن **Tajawal** ونزّله (ترخيص مفتوح OFL).
2. انسخ `Tajawal-Regular.ttf` و`Tajawal-Bold.ttf` إلى المجلد `fonts` داخل المشروع.
3. أعد البناء `npm run dist`. إن لم يوجد الملفان يُستخدم خط Dubai أو Segoe UI تلقائيًا.

## رفع إصدار جديد بدون أوامر (release.bat)
1. غيّر `"version"` في `package.json` إلى رقم أكبر من المثبّت.
2. انقر مرتين على **`release.bat`**، والصق التوكن عندما يطلبه (لا يُحفظ في أي ملف).
3. افتح صفحة Releases على GitHub، افتح المسودة واضغط **Publish release**.

### بدون توكن (يدويًا)
من GitHub: Releases ← Draft a new release ← Tag: `v` + رقم الإصدار (مثل `v1.7.1`) ← ارفع من مجلد `dist` الملفات:
`ShopAccounts Setup <الإصدار>.exe` و`latest.yml` و`ShopAccounts Setup <الإصدار>.exe.blockmap` ← Publish.

## الأيقونة القديمة على سطح المكتب
ويندوز يخزّن الأيقونات مؤقتًا. ألغِ تثبيت النسخة القديمة واحذف اختصارها، ثم شغّل **`fix_icon.bat`**، ثم ثبّت المثبّت الجديد.
